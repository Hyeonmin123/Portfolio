Echofall · 메아리의 탑2026.09 – 2026.11Jira로 관리

Echofall을 개발하면서 나온 결함과 피드백을 Jira에 버그 22건으로 정리하고, 같은 문제가 다시 생기지 않는지 확인하는 테스트 케이스 21건을 썼습니다.

  • 22버그 (모두 수정 완료)
  • 21테스트 케이스 (미실행)
  • 3열려 있는 항목

테스트 케이스는 아직 실행하지 않았습니다. 결함은 제가 직접 플레이하며 찾았거나 개발 중 커밋 기록에 남은 것입니다. 기록을 Jira 이슈로 옮기고 테스트 케이스 초안을 쓰는 데는 AI(Claude)의 도움을 받았습니다.

정리한 방식

  • Jira 에픽 하나(Echofall QA) 아래에 업무 유형을 버그, 테스트 케이스, 작업으로 나눠 등록했습니다.
  • 버그에는 증상, 조치, 발견일, 근거(직접 플레이인지 커밋 기록인지), 확인할 테스트 케이스 번호를 적었습니다.
  • 테스트 케이스에는 목적, 근거가 된 버그 번호, 사전 조건, 절차, 기대 결과를 적었습니다.
  • 레벨 번호는 "17(4-2)"처럼 순번과 막-레벨을 함께 적었습니다.

출처는 2026-10-06부터 2026-11-12까지의 작업 대화 기록과, 2026-09-24부터 2026-11-09까지의 git 커밋 123개입니다. 10월 6일 이전 항목은 커밋 메시지가 근거라서 누가 찾았는지는 알 수 없습니다.

테스트 케이스 21건

버그마다 "고친 뒤에 무엇을 해 보면 다시 생겼는지 알 수 있는가"를 기준으로 썼습니다. 아래는 그중 하나입니다.

KAN-37 감시자 유예 시간은 처음 움직일 때부터 흐르고, 감시자는 벽 밖에서 생성된다

목적
감시자의 시작 조건과 생성 위치가 규칙대로인지 확인
근거
KAN-18(가만히 서 있어도 유예 시간이 줄었음), KAN-14(감시자가 벽 속에서 생성됨)
대상
5막 이후 감시자가 나오는 레벨, 도전 레벨 7~9
절차
  1. 감시자가 나오는 레벨에 들어간다.
  2. 아무 키도 누르지 않고 10초 이상 가만히 서 있는다. 감시자가 움직이는지 본다.
  3. 그 뒤 처음 움직이고, 감시자가 쫓아오기 시작할 때까지의 시간을 잰다.
  4. 레벨을 다시 시작해, 이번에는 들어가자마자 움직이고 같은 시간을 잰다.
  5. 감시자가 처음 나타나는 위치가 벽 타일과 겹치는지 확인한다.
기대 결과
  • 가만히 서 있는 동안에는 감시자가 쫓아오지 않고 유예 시간도 줄지 않는다.
  • 3번과 4번에서 잰 유예 시간이 같다.
  • 감시자는 항상 벽 밖의 빈 공간에서 생성된다.
